# 实现说明

给接手的人和 Agent 读：读完知道东西在哪、为什么这样做、怎么改、怎么验证。写现在的样子，不写开发过程；某一节和本项目无关就写"无"，不要硬凑。

## 整体结构

由哪几部分组成，各管什么、在哪里，彼此怎么连接。

## 关键机制

主要流程怎样一步步走；重要的技术取舍和理由。

## 数据与接口

存什么数据、存在哪里、什么格式；对外提供或依赖哪些接口和服务。

## 约定

新增或修改时要遵守的做法，以及可以照着写的现有例子。

## 限制和容易踩的坑

看起来能改、其实不能随便改的地方；平台、兼容、性能等限制。

## 怎么运行和测试

命令写在项目规则的"构建与测试"；这里写测试覆盖了什么、哪些要人工检查。
