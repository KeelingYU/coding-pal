# 界面阶段

只在有界面时进入。目标：写正式代码前，让用户点一个演示页，看到效果并确认。

1. 用户的偏好不明确时，先用同一个核心页面做 2~3 个风格明显不同的方向，请用户选一个，或说要混合哪些部分。
2. 做可点击的静态演示页，放在任务文件夹（`pal path task <任务>`）的 demo/ 里，用浏览器直接打开就能看。不改项目代码，技术做法到方案阶段再定。覆盖主要流程的每个页面，以及没有数据、出错、加载中等特殊状态；用贴近真实的内容。
3. 交付前自己在浏览器里点一遍。告诉用户怎么打开、按什么顺序点、特殊状态在哪里切换。
4. 按意见修改，直到用户确认。意见改变了需求时，同步改需求说明，告诉用户改了哪条。需求说明里"留到界面再定"的事，在这里一起定下。
5. 用户确认后：阶段改为方案，在决定记录记一条，接着做方案。
